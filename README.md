# Mutual fund facts assistant

A facts-only FAQ assistant that answers factual questions about three mutual fund schemes using official AMC, AMFI and SEBI sources, cites the exact source behind every answer, and refuses investment advice. Its differentiator is not that it answers queries, but that it tracks the boundary of what it does not know. The backend tracks four verification states per fact, maintains a coverage map, and quarantines unverified facts so they are unreachable rather than merely discouraged. Built as a six-day student project exploring grounded retrieval, deterministic safety guards, and source provenance.

## The problem

Mutual fund facts are public but scattered. The minimum SIP sits in a Key Information Memorandum (KIM), the exit load in the Scheme Information Document (SID), the expense ratio on a daily disclosure webpage, the riskometer on a monthly cycle, the lock-in in statutory regulation, and the statement download process with the platform rather than the fund house. A single user inquiry can span three organisations and four document types.

Because finding these documents is slow, retail investors route around official sources to whatever research aggregator is fastest. Those answers are frequently stale, oversimplified, or wrong, with no provenance provided.

During source research for this project, three well-known financial portals gave three different figures for the same scheme's minimum SIP. The discrepancy was real: the minimum genuinely has six different values depending on frequency, each with its own instalment condition. Every one of those third-party sites picked a single branch and dropped the conditions.

This evidence established the core product principle: **do not oversimplify a financial fact when the official source contains conditions.**

## Product decisions worth defending

The decision log in `docs/decision_log.md` records 50 entries detailing alternatives evaluated and trade-offs made. Several key decisions define the product approach:

- **D001: Product context and corpus scope are separate axes.** The product framing is Groww, but the corpus is SBI Mutual Fund. Separating the platform from the asset management company prevents collapsing the multi-tier sourcing architecture into a single internal documentation lookup.
- **D017: The AMC is deliberately not Groww's own fund house.** If the platform and the fund house were the same entity, platform help articles and statutory SID filings would share the same authority. Using an external fund house forces the pipeline to enforce statutory priority over platform copy.
- **D029: Context-dependent facts are never reduced to a single value.** When a fact has conditions (such as minimum SIP varying across daily, weekly, monthly, and quarterly schedules), the system reports the breakdown and pointers to other frequencies rather than guessing a single number.
- **D030: Four verification states instead of a binary.** Facts are classified as verified, conditional, pending, or conflict-quarantined. Quarantined facts are barred from indexing at build time, ensuring unverified data cannot be retrieved or generated by a language model.
- **D042: Permission questions are factual, recommendation questions are advice.** "Can I redeem after three years?" asks about statutory liquidity rules (factual). "Should I redeem now?" asks for a portfolio judgment (advice). The advice guard distinguishes grammatical intent rather than relying on keyword blacklists.
- **D047: Held-out cases are never tuned against.** When a held-out test case fails, the underlying bug is diagnosed and resolved, the test is moved to the regression suite, and a new unseen question replaces it in the held-out set.
- **D050: Send structure rather than a string to be re-parsed.** Factual endpoints send explicit `fact_label` and `fact_value` fields from the ground-truth table. Relying on client-side regex to split prose strings fails in financial domains where periods appear inside numbers, currency abbreviations, and decimals.

## Scope and non-goals

The system operates on a deliberate, verified boundary:

- **Product context:** Groww platform surface.
- **Corpus:** SBI Mutual Fund, three schemes:
  - SBI Large Cap Fund (formerly SBI Bluechip Fund)
  - SBI Flexicap Fund (formerly SBI Magnum Multicap Fund)
  - SBI ELSS Tax Saver Fund (formerly SBI Long Term Equity Fund)
- **Source tiers:**
  - **Tier 1 (AMC):** Scheme facts, minimums, exit loads, expense ratios, benchmarks, KIM and SID filings.
  - **Tier 2 (SEBI, AMFI):** Regulatory limits, ELSS statutory lock-in, riskometer methodology.
  - **Tier 3 (Groww Help Centre):** Platform statement downloads and tax report navigation.

Groww official help documentation is a valid Tier 3 source for platform navigation. Groww promotional blog articles are not. That distinction is recorded as decision D002.

**Non-goals:** The assistant does not provide investment advice, scheme recommendations, portfolio construction, return projections, performance rankings, or financial planning. It does not process transactions or handle personal investor accounts.

## Architecture

```
Question
   ↓
PII guard              deterministic, runs before any logging or model call
   ↓
Topic detection        local synonym lookup, no network latency
   ↓
Advice guard           topic-aware, permission vs recommendation
   ↓
Scheme resolution      aliases first, then selector, then disambiguation
   ↓
LLM intent (fallback)  closed enum classification, runs only on unmatched queries
   ↓
Retrieval              metadata filter, lexical coverage gate, BM25 + dense
   ↓
Generation             grounded LLM synthesis, or extractive zero-hallucination fallback
   ↓
Citation validation    must resolve to an approved source URL
   ↓
Freshness              as-of dates, staleness flags for dynamic disclosures
```

### Pipeline ordering rationale

1. **PII guard runs first:** Blocked messages are intercepted before any database logging or external network call, ensuring sensitive identification numbers never leave the local environment.
2. **Deterministic topic detection precedes advice checking:** Distinguishing factual liquidity rules from subjective advice requires knowing the underlying topic.
3. **Guards precede LLM intent fallback:** The LLM intent classifier only processes unblocked queries that fail local synonym lookup. `backend/tests/test_intent_safety.py` asserts with a spy classifier that blocked queries never reach an external API.
4. **Coverage gate precedes generation:** Lexical coverage checks prevent generating answers when the corpus lacks grounding evidence.

## Guardrails

- **PII guard:** Scans inputs for Indian Permanent Account Numbers (PAN), 12-digit Aadhaar numbers, 10-digit mobile numbers, bank account sequences, email addresses, and 6-digit OTP codes. Matched values are never echoed in logs or responses. The OTP pattern was added after held-out testing revealed 6-digit verification codes slipping past account filters.
- **Advice guard:** Categorises requests across five refusal branches (buy/sell, fund selection, portfolio review, return prediction, personal financial planning). It redirects users to the factual criteria required to evaluate decisions independently.
- **Hallucination guard:** Verification state gates corpus construction. Facts marked as pending or conflicted are omitted from the retriever index. The system does not rely on prompt engineering alone to suppress unverified data.
- **No-evidence guard:** A lexical coverage gate validates keyword overlap against candidate text before admitting chunks to the context. Score normalisation (min-max) always assigns the highest candidate a score of 1.0, making raw similarity scores incapable of signalling complete corpus absence.
- **Citation validator:** Every citation URL is cross-checked against a whitelist of 26 approved primary sources. Generic homepages are rejected.
- **Freshness tracking:** Facts are marked as static (scheme Kim/SID), dynamic daily (Total Expense Ratio), or dynamic monthly (Riskometer). When dynamic values exceed disclosure thresholds (7 days for TER, 45 days for Riskometer), the UI marks the provenance block with an amber staleness notice.
- **Mixed intent handling:** Questions combining a factual query with an advice request (for example, "What is the exit load and should I exit?") answer the factual clause and append an indented refusal note for the advisory clause.

## Data and sourcing

The repository maintains 26 primary sources documented in `data/sources.csv`:
- 18 Tier 1 sources from SBI Mutual Fund (SID, KIM, daily TER disclosures, factsheets).
- 4 Tier 2 sources from SEBI and AMFI (categorisation circulars, riskometer methodology).
- 4 Tier 3 sources from Groww official help articles (statement downloads, capital gains workflows).

### Conflict resolution policy

When sources present differing figures, statutory filings (SID/KIM) supersede platform articles. When platform documentation conflicts with itself, the fact is quarantined in `data/ground_truth.csv` with a `CONFLICT` status and omitted from the index until verified.

### Three distinct dates

Provenance metadata tracks three separate timestamps:
1. `fact_as_of`: The date the financial figure represents (such as a daily TER disclosure date).
2. `source_dated`: The publication date of the statutory document.
3. `retrieved_at`: The date the file was downloaded by the maintainer.

Labelling download dates as "as of" dates is avoided because it overstates data currency.

Data collection is manual. SBI Mutual Fund disallows automated scraping on its document endpoints and its scheme pages render client-side, returning interface navigation rather than raw text.

## Evaluation

Evaluation is measured programmatically against `data/ground_truth.csv` and `data/eval_set.csv` rather than through subjective inspection.

The test setup uses two separate harnesses:
1. **Regression suite (`run_eval.py`):** 50 test cases covering direct lookups, paraphrasing, historical aliases, advice queries, PII attempts, feasibility checks, and known gaps.
2. **Held-out suite (`run_holdout.py`):** 29 unseen questions constructed to test generalisation across rephrasings and edge cases without tuning.

### Regression suite results (50 cases)

| Metric | Score | Target |
|---|---|---|
| Routing accuracy | 50/50 (100%) | 100% |
| Retrieval accuracy | 21/21 (100%) | 100% |
| Citation present | 21/21 (100%) | 100% |
| Refusal accuracy | 11/11 (100%) | 100% |
| PII leaks | 0 | 0 |
| Latency p50 / p95 | 0.2ms / 0.4ms | < 50ms |

### Held-out suite results (29 cases)

- Overall accuracy: 26/29 (90%).
- First run scored 70% before fixing underlying guard and alias gaps.
- The 30 percentage-point gap between the regression suite (100%) and the initial held-out run (70%) demonstrated how standard evaluation suites overstate performance on tuned inputs.

### Evaluation limitations

The author wrote both the codebase and the held-out questions, meaning the held-out suite tests generalisation beyond exact phrases but cannot surface blind spots the author failed to conceive. Independent adversarial testing exposed four routing failures that the initial test suites missed.

## What it gets wrong

- **Three held-out cases still fail:** Three held-out test cases return false refusals. They remain open to avoid overfitting synonyms to the held-out data.
- **Four facts are quarantined:** Large Cap minimum SIP, Large Cap investment objective, ELSS minimum application amount, and the Groww capital-gains flow are unreachable because their source documentation was incomplete or contradictory.
- **Factsheet data snapshot:** The latest factsheet available during collection was March 2026. Riskometer values rely on KIM snapshots and are marked conditional.
- **Lexical coverage sensitivity:** Paraphrases sharing zero vocabulary with indexed chunks can trigger false no-evidence refusals.
- **Corpus scale calibration:** Retrieval thresholds were tuned on three schemes and require recalibration as more funds are indexed.
- **Seven-day TER window:** Expense ratios under seven days old display without a staleness notice, even though TER can fluctuate daily.
- **Rule-based advice guard:** The advice guard runs on deterministic rules; a learned classifier layer is specified but not yet integrated.

## Bugs worth reading about

- **Wrong-scheme retrieval bug:** A query returned a fluent answer with a valid citation, but for the wrong scheme. The test harness had bypassed the API routing layer by invoking the pipeline directly, allowing the bug to persist on user-facing paths.
- **Ledger truncation bug:** The frontend coverage ledger initially showed false gaps for Flexicap exit load and expense ratio because it consumed an array capped for a chip component.
- **Decimal value split bug:** An expense ratio of 1.25% was displayed as 1 because client-side formatting split the message on the first period. In financial text, periods represent decimals and abbreviations more often than sentence terminators.
- **Conflicting eligibility gates:** Two retrieval filters interacted improperly, causing an exact chunk to score 0.11 against a 0.12 minimum threshold and triggering an erroneous fallback.

## Running it

### Prerequisites

- Python 3.10+
- Node.js 18+ and npm

### Backend setup

```powershell
cd backend
pip install fastapi uvicorn rank_bm25 pydantic
python -m uvicorn app.api:app --reload --port 8000
```

The backend starts at `http://localhost:8000`. API documentation is available at `http://localhost:8000/docs`.

### Frontend setup

```powershell
cd frontend
npm install
npm run dev
```

The web interface starts at `http://localhost:3000`.

### Environment variables (optional)

Create a `.env` file in `backend/` using `backend/.env.example` as a template:

```env
# Optional: LLM intent classification on unmatched queries
GROQ_API_KEY=your_groq_key

# Optional: LLM answer generation (options: groq, gemini, or none)
MF_LLM=none
GEMINI_API_KEY=your_gemini_key
```

When no API key is provided, the assistant uses extractive synthesis directly from retrieved chunks.

### Running evaluation suites

```powershell
cd backend/tests
python run_eval.py
python run_holdout.py
```

## Disclaimer

This assistant provides factual information compiled exclusively from selected official Scheme Information Documents (SID), Key Information Memorandums (KIM), AMFI, and SEBI regulatory filings. It does not provide investment, financial, taxation, or portfolio allocation advice. Do not submit personal identifiable information (PAN, Aadhaar, account credentials, OTPs, or contact numbers).
